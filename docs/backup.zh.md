# 备份与恢复

语言：[English](backup.md) · [فارسی](backup.fa.md) · [Русский](backup.ru.md) · **中文**

钱在 Shop 的数据库里，账户在面板的数据库里，所以要保管两个数据库。面板备份它自己的；Shop 在这里备份它自己的。

## 备份是什么

Shop 数据库（在 Shop 运行时取得的一致副本）和卡对卡转账凭证的归档，用只有您保管的密钥加密。在 Shop 管理后台的 **备份** 中：

| 设置 | 默认值 | |
| --- | --- | --- |
| 每隔几小时备份一次 | `24` | `0` 关闭定时备份 |
| 服务器上保留的归档数量 | `7` | 更早的归档会被删除 |
| 向服务器外发送一份副本 | 开启 | 发送到面板的备份群组，或通过 Shop 的机器人发送 |

归档写入 `data/backups/`，文件名为 `shop-<date>-<time>.nxsb`，每个都可以在同一页面下载。**立即备份** 会马上做一次备份。

**服务器外的副本** 通过面板自己的机器人发送到您在面板上为备份选择的 Telegram 群组（**服务 → 备份目的地 → Telegram**）——Shop 永远看不到这个群组。如果面板上关闭了该功能，副本会通过 Shop 的机器人发送给每位已绑定的管理员。Telegram 只接受 50 MB 以内的文件：更大的归档会留在服务器上，页面会说明。面板无法读取归档，Telegram 也不能。

使用 **PostgreSQL** 时，数据库由您管理，其备份也由您负责：和该服务器上的其他数据一样用 `pg_dump`。此时 Shop 的归档只包含凭证，并会注明。

## 密钥

**备份** 中的 **显示密钥** 会显示能打开所有归档的密钥（`nxsb-…`）。请把它复制到安全的地方，不要放在本服务器上：归档只能用它打开，服务器丢失时，服务器上的那份密钥也会一起丢失。密钥不会改变；用它做的归档永远可以用它打开。

## 迁移到新服务器

1. 照常在新服务器上安装 Shop，然后停止它（`systemctl stop nexora-addon-shop`，或 `docker compose stop shop`）。
2. 把归档复制过去，用密钥恢复：

   ```sh
   nexora-shop restore -i shop-20261004-120000.nxsb -key nxsb-…
   ```

   使用 docker 时：`docker compose run --rm shop restore -i /data/backups/shop-….nxsb -key nxsb-…`（先把归档复制到 `data/backups/`）。
3. 重新启动 Shop。

恢复前会先检查密钥，并确认归档中的数据库是 Shop 的，然后才动任何东西；被替换的内容保留为 `shop.db.before-restore` 和 `receipts.before-restore`。密钥错误或归档损坏时不会改动任何东西。面板注册信息不在归档中：如果新服务器沿用旧地址，请一并复制 `data/nexora-credentials.json`；否则请在面板的扩展页面移除 Shop 并重新注册。

`nexora-shop backup` 用同一个密钥手动生成归档。

## 面板恢复之后

面板从备份恢复后，其账户会回到备份时的状态——Shop 此后售出的内容可能已从面板上消失。面板会通知 Shop（`panel.restore_applied`），Shop 会把它售出的每个账户与面板比对。面板上已不存在的账户，或到期日、流量少于 Shop 最后一笔订单所给的账户，会列在 **备份 → 面板恢复之后** 中，并附上为其付款的订单，概览页会显示未处理的数量。请逐个手动处理——在面板上续费，或为订单退款——然后标记为 **已处理**。**立即检查** 可随时运行同样的检查。
