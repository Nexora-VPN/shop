# 折扣码、礼品码和推荐

语言：[English](promotions.md) · [فارسی](promotions.fa.md) · [Русский](promotions.ru.md) · **中文**

三者都在管理后台的 **优惠码** 页面设置。客户在机器人和网页应用中使用它们；与它们相关的任何内容都不会传到面板。

## 折扣码

折扣码按**百分比**或**金额**减免一个订单。可以限制：

- **时间范围**：开始日期、结束日期，或两者；
- 所有客户合计的**使用次数**（0 为不限），以及**每位客户一次**（默认开启）；
- **商品**：部分商品，或全部商品；
- **购买类型**：新服务、续费、加流量。

客户在选择商品之前输入折扣码：机器人的列表中有 **我有优惠码** 按钮，网页应用的购买页面有 **有优惠码吗？** 链接。随后列表显示每个商品使用该码后的价格；不在该码范围内的商品保持原价，购买时不使用该码。不适用的折扣码会被拒绝并说明原因：不存在、已关闭、未开始、已过期、已用完、不适用于该商品或该购买类型、该客户已使用过。

**占用。** 使用折扣码下单但尚未付款的订单会占用该码的一次使用 **24 小时**，因此最后一次使用不会同时给两个买家，也不会被中途离开的人一直占着。取消订单会立即归还其使用次数；占用过期则自动释放。占用过期后才付款的订单仍按客户当时看到的价格成交，并计入使用次数——所以一笔迟到的付款可能让折扣码超出上限一次。

折扣码使其免费的订单会立即视为已付款并开通服务；不发生资金流动。折扣码从不进入钱包账本：订单只是要求付更少的钱。删除已被订单使用过的折扣码时，会改为将其关闭；这些订单保留它的名称。

## 礼品码

礼品码向客户钱包存入一笔**金额**——用于促销或补偿——**每位客户一次**，可选设置结束日期和使用次数。在机器人中它位于钱包界面（**礼品码**），在网页应用中位于钱包页面。钱包随后够支付的订单会立即付款：有未付款订单的客户可以用礼品码支付。折扣码和礼品码共用一个命名空间——客户输入代码时无需说明是哪一种。

## 推荐

开启推荐后，每位客户都有自己的推荐链接：

- 机器人的：`https://t.me/<bot>?start=ref_<code>`（菜单中的 **邀请好友**）；
- 网页应用的：`https://<shop>/app/?ref=<code>`（钱包页面）。

**首次**通过链接来的客户永久归属该推荐人：推荐关系在创建客户时绑定，此后任何东西都无法改变——其他推荐人的链接不行，管理员也不行。打开链接时已经是商店客户的人，不归属任何人。Telegram 客户与网页客户合并时，保留下来的一方保持自己的推荐关系；从未购买过且不归属任何人的一方则继承另一方的推荐关系——那是同一个人的首次启动。

奖励在 **推荐** 中设置：

- 被推荐客户每笔付款订单的 **每笔订单的百分比**——或开启 **百分比仅限首单** 时，只按第一笔订单计算；
- **首单固定金额**，以商店货币计；
- 两者都设，或都不设（两者都为零：推荐关闭，不显示链接）。

奖励在**面板创建订单后**进入推荐人钱包，而不是仅仅付款后——面板拒绝的订单会被退款——推荐人会在机器人中收到通知。试用或被折扣码变为免费的订单不产生奖励。订单退款会收回奖励，以推荐人钱包中尚存的金额为限。**第一笔订单** 是面板创建的第一笔有实际付款的订单；已退款的第一笔订单仍算作第一笔。

## API

管理员的路由（需登录）：

| 路由 | 作用 |
| --- | --- |
| `GET /api/discounts` | 所有折扣码，及其使用次数、当前占用次数和状态 |
| `POST /api/discounts`, `PUT /api/discounts/{id}` | 创建、编辑——未提供的字段保持原值 |
| `DELETE /api/discounts/{id}` | 删除；已被订单使用过的会改为关闭 |
| `GET /api/discounts/{id}/redemptions` | 使用了该码的订单 |
| `GET`/`POST /api/gifts`, `PUT`/`DELETE /api/gifts/{id}` | 礼品码的相同操作 |
| `GET`/`PUT /api/settings/referral` | `percent`、`firstOnly`、`fixed` |
| `GET /api/referrals` | 已发放的奖励，最新的在前 |

客户的路由（`/api/c`，bearer 令牌）：`POST /quote`（`code`、`kind`）返回该码对每个商品的减免；`POST /orders` 接受 `code`；`POST /gift` 兑换礼品码；`GET /referral` 返回客户的链接和收益。被拒绝的代码返回 **422** 和 `reason`。登录接口（`/login/verify`、`/login/telegram`）接受链接中的 `ref`；小程序还会从其启动参数中读取 `ref_<code>`（`t.me/<bot>?startapp=ref_<code>`）。
