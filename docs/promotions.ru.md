# Промокоды, подарочные коды и рефералы

Языки: [English](promotions.md) · [فارسی](promotions.fa.md) · **Русский** · [中文](promotions.zh.md)

Всё это настраивается на странице **Коды** в админке. Клиент пользуется ими в боте и в веб-приложении; в панель ничего из этого не попадает.

## Промокоды

Промокод снимает **процент** или **сумму** с одного заказа. Его можно ограничить:

- **периодом**: датой начала, датой окончания или обеими;
- **числом использований** на всех клиентов (0 — без ограничений) и **одним разом на клиента** (по умолчанию включено);
- **товарами**: некоторыми или всеми;
- **типами покупки**: новые услуги, продления, докупка трафика.

Клиент вводит код до выбора товара: в списке бота есть кнопка **У меня есть промокод**, на странице покупки в веб-приложении — ссылка **Есть промокод?**. После этого список показывает цену каждого товара с учётом кода; товар, на который код не распространяется, сохраняет свою цену и покупается без кода. Неподходящий код отклоняется с указанием причины: не существует, выключен, ещё не действует, истёк, исчерпан, не для этого товара или типа покупки, уже использован этим клиентом.

**Резерв.** Заказ, оформленный с кодом и ещё не оплаченный, резервирует одно использование кода на **24 часа**, чтобы последнее использование не досталось сразу двум покупателям и не застряло у того, кто ушёл. Отменённый заказ сразу возвращает использование; истёкший резерв освобождается. Заказ, оплаченный после истечения резерва, всё равно принимается по цене, которую видел клиент, и засчитывается — поэтому поздняя оплата может превысить лимит кода на одно использование.

Заказ, который код сделал бесплатным, сразу считается оплаченным, и услуга создаётся; деньги не движутся. Код никогда не попадает в книгу кошелька: заказ просто стоит меньше. Если удалить код, по которому уже были заказы, он вместо этого выключается; эти заказы сохраняют его название.

## Подарочные коды

Подарочный код зачисляет **сумму** на кошелёк клиента — для акции или в качестве компенсации — **один раз на клиента**, с необязательной датой окончания и числом использований. В боте он находится на экране кошелька (**Подарочный код**), в веб-приложении — на странице «Кошелёк». Всё, что кошелёк после этого покрывает, оплачивается сразу: клиент с неоплаченным заказом может оплатить его подарком. Промокоды и подарочные коды живут в одном пространстве имён — клиент вводит код, не уточняя, какого он типа.

## Рефералы

У каждого клиента своя реферальная ссылка; она показывается, когда рефералы включены:

- в боте: `https://t.me/<bot>?start=ref_<code>` (кнопка меню **Пригласить друзей**);
- в веб-приложении: `https://<shop>/app/?ref=<code>` (страница «Кошелёк»).

Клиент, который **впервые** пришёл по ссылке, навсегда закрепляется за пригласившим: реферал привязывается при создании клиента, и после этого его ничто не меняет — ни ссылка другого пригласившего, ни администратор. Клиент, который уже был в магазине, когда открыл ссылку, ни за кем не закрепляется. Когда клиент из Telegram и клиент из веб-приложения объединяются, остающийся сохраняет свой реферал; если он ничего не покупал и ни за кем не был закреплён, он получает реферал второго — это первый вход того же человека.

Награда настраивается в блоке **Рефералы**:

- **процент с каждого заказа**, который оплачивает приглашённый клиент, — или, если включено **Процент только с первого заказа**, только с первого;
- **фиксированная сумма за первый заказ** в валюте магазина;
- и то и другое или ничего (оба нуля: рефералы выключены, ссылки не показываются).

Награда идёт на кошелёк пригласившего, **когда панель создала заказ**, а не просто когда он оплачен (заказ, который панель отклонила, возвращается), и пригласившему приходит сообщение в боте. Пробный период и заказ, который код сделал бесплатным, ничего не приносят. При возврате заказа награда забирается обратно — насколько её ещё хватает в кошельке пригласившего. **Первый заказ** — это первый заказ с деньгами, который создала панель; возвращённый первый заказ всё равно остаётся первым.

## API

Маршруты администратора, после входа:

| Маршрут | Что делает |
| --- | --- |
| `GET /api/discounts` | все промокоды с числом использований, текущими резервами и состоянием |
| `POST /api/discounts`, `PUT /api/discounts/{id}` | создать, изменить — не переданное поле сохраняет значение |
| `DELETE /api/discounts/{id}` | удалить; код, по которому были заказы, выключается |
| `GET /api/discounts/{id}/redemptions` | заказы, к которым он применён |
| `GET`/`POST /api/gifts`, `PUT`/`DELETE /api/gifts/{id}` | то же для подарочных кодов |
| `GET`/`PUT /api/settings/referral` | `percent`, `firstOnly`, `fixed` |
| `GET /api/referrals` | выплаченные награды, сначала новые |

Маршруты клиентов (`/api/c`, bearer-токен): `POST /quote` (`code`, `kind`) отвечает, сколько код снимает с каждого товара; `POST /orders` принимает `code`; `POST /gift` активирует подарочный код; `GET /referral` — ссылки и заработок клиента. Отклонённый код отвечает **422** с полем `reason`. Входы (`/login/verify`, `/login/telegram`) принимают `ref` из ссылки; мини-приложение также читает `ref_<code>` из своего стартового параметра (`t.me/<bot>?startapp=ref_<code>`).
